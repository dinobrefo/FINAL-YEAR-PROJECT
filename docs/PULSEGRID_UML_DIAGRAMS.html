4. Sequence Diagram: Pre-Arrival Bed Lock & Fan-out

Real-time Telemetry Broadcast

Atomic database transactions lock critical beds before arrival, triggering simultaneous WebSocket broadcasts to emergency physicians and city dispatchers.

sequenceDiagram autonumber actor Paramedic as Paramedic HUD participant Gateway as Express Gateway & Socket.IO participant DB as PostgreSQL (ACID Transaction) actor Doctor as Hospital ER Console actor Command as National Command Center Paramedic->>Gateway: POST /api/cases/EMG-004/accept-route (Target Hospital: KATH) activate Gateway Gateway->>DB: BEGIN TRANSACTION; activate DB Gateway->>DB: SELECT * FROM hospitals WHERE id = 'KATH' FOR UPDATE; Gateway->>DB: UPDATE hospitals SET available_icu_beds = available_icu_beds - 1 WHERE id = 'KATH'; Gateway->>DB: UPDATE emergencies SET status = 'in-transit', assigned_hospital = 'KATH' WHERE id = 'EMG-004'; Gateway->>DB: COMMIT; DB-->>Gateway: Transaction Committed Successfully deactivate DB par Real-Time Fan-out via Socket.IO Gateway->>Doctor: WS: INCOMING_TRAUMA_ALERT (Case EMG-004, ETA 4 mins, TEWS 8, Bed: ICU-02) Doctor->>Doctor: Trigger Audio Alarm & Display Pre-Arrival Trauma HUD and Gateway->>Command: WS: TELEMETRY_GRID_UPDATE (Unit AS-112-21 En-route, KATH ICU Load +1) Command->>Command: Update 3D Hospital Capacity Mesh & Map Hotspot and Gateway-->>Paramedic: HTTP 200 (Bed Locked, Begin Voice HUD Navigation) end deactivate Gateway
Examiner Defense Point: The SELECT ... FOR UPDATE statement guarantees ACID serializability, preventing race conditions where two ambulances heading to the same hospital simultaneously claim the final ICU bed.
